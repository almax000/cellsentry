# PII mmBERT v2 量化验证与 Issue #2 核对

**体积可以通过量化达标；不能把1.23 GB原始权重视为模型路线无法满足500 MB上限的证据。** 本次Q8权重约309.68 MB（含分类头），加上tokenizer/config/脚本约344 MB。但这不是GGUF，也未解决所有准确率或端侧运行要求。

## 固定模型与阈值的64份回归

| 版本 | 严格精确率 | 严格召回率 | 严格 F1 | TP / FP / FN |
|---|---:|---:|---:|---:|
| 原版 CUDA BF16计算 / FP32权重 | 90.65% | 69.04% | 78.38% | 223 / 23 / 100 |
| 原版 CPU FP32 | 90.65% | 69.04% | 78.38% | 223 / 23 / 100 |
| 首次动态 INT8 | 96.72% | 18.27% | 30.73% | 59 / 2 / 264 |
| Q8仅量化权重，FP32计算 | 91.43% | 69.35% | 78.87% | 224 / 21 / 99 |

第一次动态INT8同时改变Linear计算的激活量化，体积309.23 MB，但准确率下降明显，未作为发布版本。另导出固定的逐行权重量化版本：Linear采用每输出行对称int8，Embedding每行仿射uint8；保留浮点激活、归一化和分类头。它按需反量化当前层权重进行FP32计算，不等于优化后的INT8矩阵乘运行时。仅权重Q8导出不调用训练、反向传播或校准语料。

先用独立开发集的前128个候选核对：相对原版开发预测类别翻转0，最大概率差0.00002867；再对64份已见回归执行固定版本测试。源模型step400、阈值0.95、候选代码和原金标均未修改，64份未进入训练或量化校准。0.49个百分点的F1变化是本套小回归上的数值边界变化，不是量化使泛化能力提高的证据。

原版CPU FP32的446候选推理51.84秒；动态INT8为23.16秒；Q8权重版为67.05秒。均在当前Windows CPU、4线程上测量，不含构造/加载；不是Mac性能测试，不满足每千候选2秒的证明。Q8节省存储与常驻权重，但每层反量化会有额外开销；没有测定iPhone峰值内存。

## #2 是否完成

| 原验收项 | 当前证据 | 状态 |
|---|---|---|
| 模型≤500 MB | Q8权重309.68 MB、整包约344 MB | 体积可达标；格式尚未接入产品 |
| 结构化标识文档残留0 | 原版原360份为72.5%；Q8在64份回归上为23.44% | 未达标；两套数据比例不可直接比较 |
| 姓名/地址召回：结构化≥95%、自由文本≥85% | 原版姓名为0.52% / 1.04%，地址100% / 97.92%；Q8原360份未全量重测 | 姓名失败，未证明量化版已修复 |
| 阴性误报≤5% | 原版原360份纯阴性文档误报1.39%；Q8的64份为0 | 已有合成回归指标通过，不代表真实场景可靠 |
| B不劣于C | 未完成token分类模型对照；B现已改为自训mmBERT，而非Julia-1 | 未完成 |
| Mac每千候选≤2秒、报告峰值内存 | 当前只有Windows GPU/CPU结果 | 未完成 |

因此不应关闭#2。用户已调整为自训mmBERT路线，Julia-1本身不必作为固定实现；但token分类路线对照、验收数据和Mac性能仍需补齐。此次只读取issue，没有修改其正文、勾选或状态。

## 发布与复现

V3原始PII模型放在`pii-mmbert-v2/`，Q8版本放在`pii-mmbert-v2-q8/`；保留既有公式模型及仓库私有可见性。不发布精度下降的动态INT8权重，不上传训练数据或64份原文。

Q8需专用`pii_q8_weight_only.py`加载自定义量化buffer，不能直接由`AutoModel.from_pretrained`或llama.cpp加载。这只是可复现的体积/精度实验，后续还需对应GGUF/原生执行路径。

原版回归的F1从93.08%退步到84.03%，仍然是已知问题；本次没有通过改测试标签、重训或调阈值来掩盖它。该旧集未对Q8全量重跑，不声称量化已解决旧场景退步。
