# 桌面脱敏引擎 v1：只用规则，冻结中文医疗集

> 历史结果：以下对应 2026-10-20 的冻结集及默认决策。2026-10-23 的 ADR-0018 将明确医护角色姓名改为默认替换，而此集将医生名标为负例；本页数值不代表当前策略的成绩。保留原 gold 与结果，后续比较另建策略版本。

**结论：test 集严格精确率 100%，召回 80%；住址召回 0%，没过 ADR-0006 的线。**

## 测了什么

- 引擎：`app/shared/redact/`，只开规则检测器。不填“我的信息”，不接模型。
- 数据：Black Sky 冻结的 `test-cases/pii-medical-v1/`，test 集 SHA256 与数据卡登记的一致。
- 评分：同目录的冻结评分器 `scripts/pii-benchmark.mjs`，严格匹配（边界和类型都对才算）。
- 计入预测的：引擎建议“换掉”的候选，不论“很确定”还是“不太确定”，也就是用户什么都不改时的默认结果。
- 体检编号、病历号这类“编号”，数据集里没有对应类别，按背景处理，不计入预测。
- 复现：`node scripts/benchmark-redact-rules.mjs test --out benchmark-results/redact-rules-v1/test-score.json`。

## 过程

1. 规则只在 dev 集上调。第一版 dev 集召回 65.7%，漏在三处：
   - 表格：表头一行、数据在下面几行；
   - 正文里“家庭住址为“……””这种带引号的写法；
   - “不含就诊人或家属标识”里的“标识”被当成人名，误报。
   补上以后，dev 集是 100%。
2. 规则定稿后，test 集只跑了一次（2026-10-20 08:22 EDT ｜ 2026-10-20 05:22 PDT ｜ 2026-10-20 20:22 UTC+8），之后**没有再按 test 集改规则**。

dev 集满分不说明规则真的好：dev 和 test 由同一个生成器按模板造，dev 的字段说法有限，规则很容易只记住这些说法。test 集换了一套字段用语和模板，才是这次该看的数。

3. 安全审查之后改了检测（全角数字转半角、号码组间允许两个空格、邮箱正则加前置边界、同一个值在所有页上再找一遍）。改完先确认 dev 集仍是 100%，再把 test 集跑了第二次（约 2026-10-20 09:31 EDT ｜ 2026-10-20 06:31 PDT ｜ 2026-10-20 21:31 UTC+8），结果和第一次完全相同，存在 `test-score-after-review.json`。这些改动来自审查发现，不是看 test 集的错例改的。

## 已知局限

- 住址全漏，原因是 test 集的住址字段标签不在规则的词表里。规则只认标签，不认地址本身的样子。改法（例如认“省市区路号室”这种地址形状）要在一份新的冻结集上量，不能再用这份 test 集。
- 产品里还有“我的信息”表：用户自己和家人的姓名、证件号、手机号、住址填进去以后会被直接找出来。这次没开，所以这是最坏情况下的数。
- 数据是合成的、文本层的，没有 OCR，也不代表真实病历。
