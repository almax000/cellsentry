# 工作簿保留集 v1：冻结前协议（2026-10-17）

本协议在任何模型看到本集数据之前写定。它把 [新保留集规范](new-holdout-specification.md) 和 [模型评测验收合同](model-evaluation-acceptance-contract.md) 落到一次具体、低成本的诊断上。它不是安全认证、市场指标或统计显著性检验；样本量和判读门槛都是待校准的诊断建议。

## 要回答的问题

在**普通工作簿上下文**（产品真实证据：原表观察值、缓存值未重算、业务要求未声明）下，对产品规则引擎**实际产生**的候选告警：

1. 规则单独、旧 Qwen（1.5b-v3）、v2 MiniCPM 的协议有效率；
2. 模型建议与独立标签的一致性，按真实错误／误报分开；
3. 真实错误被建议撤销（误撤）的数量与分母——这是产品最不能接受的失败；
4. 产品实际保留／呈现行为：产品从不自动撤销，模型反对只显示为“分歧”。因此把误撤翻译为“真实错误被标成 AI 分歧”，把正确撤销翻译为“误报被标成 AI 分歧、可减少的检查”；再按产品默认预算（每次扫描按严重程度最多 20 条）计算真正会被复核的子集。

与 480 条提供合成集的根本区别：候选由产品规则引擎从工作簿中产生，不是手写 issue；模型输入由产品 `buildAuditEvidence` 生成，不含业务要求；标签依据另行书写的业务规则，由两位互不可见的标注者独立给出。

## 来源、分组与隔离

- **来源类别**：本轮新编写的合成小微企业工作簿（`authored_synthetic_workbook`）。没有真实用户数据，因此不能声称代表真实用户分布；能声称的是与训练模板隔离、由产品真实流程产生候选。
- **分组单位**：业务家族（family）。同一家族的所有工作簿、变体、相邻行与正反事实都在同一组；本轮全部家族都属于保留集，开发调试只使用既有黄金工作簿和两条 diagnostic。
- **编写者隔离**：编写者不得读取 `training-data/`、`benchmark-results/`、`test-cases/model-coverage/`、`EXPERIMENTS.md`、`public-data/` 以及任何模型响应。编写者可读规则引擎源码以了解可检测范围，但工作簿应先满足“一个真实店主会这样做表”，不得为诱导模型失败而构造。
- **事后泄漏检查**：冻结前对公式骨架（地址归一化）、规则消息与证据文本，同 train/validation/test 的 case 输入做精确与近似重合统计，并报告家族概念与 12 个训练类别的对应关系。概念重合是正常的，模板／文本重合需要逐条列出。

## 每个家族交付的材料

位置：`evaluation/formula-holdout-20261017/families/<family>/`。该目录是评测保留集，不得用于训练、提示词修改或阈值选择；刻意不放在 `test-cases/`，因为后者的 README 声明其文件可用于训练。

| 文件 | 内容 | 谁能看 |
| --- | --- | --- |
| `generate.cjs` | 确定性生成脚本（ExcelJS），写入公式与自行计算的缓存值 | 所有人 |
| `*.xlsx` | 生成的工作簿 | 所有人 |
| `business-spec.md` | 店主真实规则，像对会计口述那样写；是标签的业务依据，不进入模型输入 | 标注者 |
| `author-ledger.json` | 编写者有意植入的错误与“少见但正确”的做法及其单元格 | **密封**：标注者在给出标签前不可见；用于事后核对和规则召回缺口 |

## 标注与裁决

1. 候选由 `scripts/build-workbook-holdout.cjs` 从工作簿经产品读取器与规则引擎生成，带工作簿 SHA、规则 ID、单元格、产品证据与产品默认排序。
2. 每条候选由两位标注者独立判断：Codex CLI（GPT 系）与一个新的 Claude 子代理。标注者可读工作簿全部内容与 `business-spec.md`，不可读 `author-ledger.json`、对方标签或任何模型输出。输出：`is_real_error`（true／false／uncertain）、一句依据、`decidable_from_evidence`（visible／partial／hidden：仅凭产品送给模型的证据能否判断）。
3. 两者一致且非 uncertain → 直接采用。不一致或任一 uncertain → 主 agent 裁决并写理由，标记 `adjudicated`；仍无法判断的列为 `excluded_uncertain`，单独报告，不进入主分母。
4. 标签冻结后才打开 `author-ledger.json` 比对；编写者意图与冻结标签不同的条目逐条列出，不回改冻结标签。

## 冻结与运行

- 冻结物：候选 manifest、最终标签、`frozen_evaluation` 语料与 manifest（含 SHA 和有序 ID）、本协议的 Git 提交。冻结提交先于任何模型运行。
- 运行：`scripts/run-formula-comparison.cjs`，与产品相同 system/user 消息、temperature 0、seed 42、max_tokens 420、context 1024、`enable_thinking=false`；开启产品同款 apply-template + tokenize 预检，超预算按产品行为不发 completion 并保留告警。旧 Qwen 与 v2 顺序运行、各用其服务端 chat template，GPU 任务串行。
- 冻结后不得因结果修改提示词、标签、候选或阈值；若发现 harness 缺陷，修复后整体重跑并保留第一次结果。

## 报告的指标

对每个模型：协议接受／失败（含预检跳过）；最小混淆矩阵（真实错误保留、真实错误误撤、误报保留、误报正确撤销）及各自分母；按 `decidable_from_evidence`、家族、规则 ID 分层；产品默认 20 条预算子集上的同一矩阵；规则单独基线（全部保留）；`author-ledger` 中植入但规则未召回的错误清单（不属于模型指标）。模型自报 confidence 只描述分布，不当概率。

## 预先写定的判读（诊断，不是科学阈值）

- v2 在 `visible` 真实错误上出现任何误撤：继续只作复核注释，不讨论自动隐藏；在报告中逐条给出可观察原因。
- v2 正确撤销的误报数接近 0：说明在普通上下文下，AI 复核尚未带来可见的检查减负；应避免对外表述“AI 减少误报”，并把下一步放在证据／上下文而非新功能。
- v2 相对旧 Qwen 的差异只在同一冻结集、同一预检和同一参数下陈述，不外推到真实用户。
- 样本量小，任何比例都附分子／分母；不做显著性结论。

## 冻结前修订记录（模型运行前）

1. **裁决者改为第三位盲审代理。** 编写工作流的返回值把部分家族的编写者摘要（含植入项描述）带回了主 agent 的上下文，主 agent 因此不再是“未见答案键”的裁决者。分歧与 uncertain 条目改由一个从未接触 `author-ledger.json`、编写者摘要或任一标注结果来源之外信息的新 Claude 子代理裁决；它只看标注包与两份标注。主 agent 只做流程与格式检查，不改标签。
2. **样本全量保留。** 16 个家族经产品规则引擎共产生 138 条候选（error 41／warning 89／info 8），超过建议的 60–100 条；为避免选择偏差，全部保留、不抽样。每个工作簿候选数都 ≤ 20，因此产品默认预算子集与全集相同，报告中注明。
3. **可复现性。** 生成脚本的单元格内容在重复运行时一致；11 个家族的 xlsx 字节因 zip 时间戳不同。冻结以已提交的 xlsx 及其 SHA 为准。
4. **泄漏检查（报告，不作门槛）。** 46/138 条与训练集公式骨架精确重合，全部是 `=SUM(REF)`、`=REF±REF`、`=REF*REF` 这类通用骨架；规则消息精确重合 0；证据文本 5-gram Jaccard 最大 0.054。另观察到训练集用合成类别名作 ruleId，产品发送真实规则 ID，二者分布不同。
