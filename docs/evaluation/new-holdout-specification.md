# 新保留集规范

## 目标

建立一个小而可审计的公式撤销复核保留集，用于检验模型是否减少人工复核负担，同时不提高真实错误被撤销的风险。建议首轮为 60–100 个候选告警、10–20 个公式／业务规则家族；这是低成本诊断，不是安全认证或市场指标。

## 取样与隔离

先按来源、工作簿、模板、公式骨架和业务规则家族分组，再分配到开发或保留集。同一公式的正反事实变体、同一模板派生样例和同一工作簿的相邻行必须在同一组。保留集在标签冻结前不得用于训练、提示词修改、阈值选择或失败例调参。

每条记录应包含可合法保留的最小上下文：候选告警、公式和单元格地址、必要的引用／依赖信息、业务规则、标签、标签依据、来源类别及去标识策略。若原工作簿不能保存，保存足以复核判断的匿名化依赖切片和双人标签说明。

## 对照与评分

在同一冻结集上分别运行规则单独、已发布 Qwen、MiniCPM v1（若需要定位训练增益）和 v2。每个运行必须使用各自正确的 chat template，并记录模型与运行时元数据。评分要分为：原始语义判断、JSON／schema／身份协议、产品实际保留／呈现行为。不要把协议失败修饰为语义成功。

报告的最小混淆矩阵为：真实错误保留、真实错误误撤、误报保留、误报正确撤销；同时列出未被规则召回的错误，避免把候选复核的表现误称为整体公式审计能力。对每个误撤样例写明可观察原因、标签不确定性和产品保护措施。

## 运行与发布门槛

先以离线审计确认输入与输出文件完整，再运行模型。模型运行不能改变 HTTP/HTTPS 代理配置。默认策略是人工复核，除非新的、独立且经复查的证据支持更自动化的行为；即使如此，应用仍需在格式失败、超时、取消和缺上下文时保留原告警。
