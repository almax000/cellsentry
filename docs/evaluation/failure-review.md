# cancel2 external580：17 条 gated unsafe withdrawal 的可审计边界

本说明基于已保存的响应、撤销分数、运行元数据和 `unsafe-withdrawals-external580.jsonl`。它没有执行模型、访问网络、恢复原始语料或读取权重。

## 能够静态核对的事实

- 静态计数为 raw 86 次撤销（65 条误报被正确撤销、21 条被提供标签标为真实错误的告警被错误撤销）；冻结 gate 为 75 次撤销（58 条正确、17 条被提供标签标为真实错误的告警被错误撤销）。17 个保存的 unsafe ID 可与 v2 响应及分数一一连接；每条均是 `expected_error=true`、`eligible=true` 且达到冻结阈值的撤销。
- 每条都附有 rule/cell/sheet、公式、规则消息、短上下文和置信度，因此可判断模型面对的是哪一种业务逻辑主张。
- 这些失败集中在范围求和含隐藏行、循环引用、XLOOKUP 查找结果、条件格式阈值和空前置单元格等公式语义。它们不是 JSON、身份或协议格式失败：保存响应可解析为单项判断。

## 不能独立核查的部分

`source_issue` 是模型输入摘要，不是原始工作簿，也没有业务规则的审阅理由。external580 的不可变 JSONL、对应源工作簿、17 条标签的独立复核记录和记录的 v2 GGUF 都不在当前证据链中。因此不能从这些材料确认“真实错误”标签，也不能判断模型是否遗漏了摘要外的依赖、隐藏数据、查找表或业务约束。

保存运行记录的 corpus SHA 与可见 v1 的 SHA 不同，Qwen 记录又来自另一份 500 条集。故不得把本材料表述为 v2 相对 v1/Qwen 的改善。

## 决策含义

冻结 gate 在外部集仍错误撤销 17 个被提供标签标为真实错误的告警，且失败包括对业务上下文敏感的计算语义。当前产品应继续保留规则告警并把 AI 判断仅作为 review 注释。把 v2 作为闭源默认模型或启用自动撤销没有可用的独立证据。

下一次可判定的验收需要：恢复带 SHA 的原始 external580 输入和相应权利/来源说明；为每个 unsafe withdrawal 保存可审计的标签理由及原始工作簿或允许的最小复现；在同一冻结集、固定模板和运行记录上实际运行 v2 与对照模型；然后用离线索引核对原始响应、分数、权重哈希和失败样例。
