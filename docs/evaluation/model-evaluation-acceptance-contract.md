# 模型评测验收合同

## 目的与边界

CellSentry 的模型评测必须把三件事分开：模型在给定候选告警上的判断、规则引擎本身的覆盖率，以及桌面产品的导入、展示、导出和恢复体验。模型只可复核已有候选告警；没有被规则发现的错误必须另列，不能混入“模型准确率”。

本合同适用于公式撤销复核。PII 与结构化提取须使用各自的任务、标签和指标，不得因公式专项训练而声称已改善。

## 每次评测必须冻结的内容

运行前记录代码提交、模型文件 SHA-256、底座和适配器版本、量化方式、运行时版本、chat template SHA-256、prompt SHA-256、上下文长度、生成参数、硬件和操作系统。保存原始输入、原始响应、评分结果和数据 manifest；不得只保存汇总表。

对每个撤销决定同时报告：真实错误被错误撤销数及其分母、误报被正确撤销数及其分母、撤销决定正确率、撤销行动覆盖率、格式／身份校验失败后保留的数量。不得将撤销决定正确率当成全体样本准确率，也不得将模型自报 confidence 当成经校准概率。

## 当前 external580 的验收状态

`benchmark-results/cancel2-external580` 已保存 v2 的响应、撤销分数、运行元数据和 17 条 gated 误撤记录，可以使用 `python3 scripts/audit_model_evidence.py` 核对静态分母和 ID 一致性。它不能构成独立重跑：原始输入 JSONL 未随仓库保存，且保存的标签未由本仓独立复审。

`comparison.json` 中的 v1/v2 汇总必须作为历史协作者材料处理，直到每一侧都能提供同一冻结语料、原始响应和运行元数据。当前可见 MiniCPM v1 external 运行的 corpus SHA-256 与 v2 不同；旧 Qwen 仅有不同的 500 条合成集记录。因此不能用这些材料主张旧 Qwen、MiniCPM v1 和 v2 已完成同语料比较。

## 通过条件

一次“独立复现”至少要求：输入 corpus 的 SHA-256 与 manifest 一致；同一冻结语料上重跑目标模型和对照；运行记录完整；脚本不改变代理配置；结果经离线审计命令验证；失败样例与标签理由可复查。达到这些条件前，表述只能是“保存结果的静态核对”或“协作者报告的历史结果”。

任何自动撤销或隐藏告警功能还需要单独的产品验收。无效 JSON、地址／规则 ID 不匹配、超时、缺模型、取消和缺上下文都必须保留原规则发现；当前离线 gate 不能被当作已集成的应用行为。
