## 背景

jojo 反馈 GitHub 的大文件下载慢且易断，要求比较面向全球的分发方案、月常规成本不超过 $5、尽量避免绑卡自动扣费，并提出把模型直接放入安装包。两轮外部调研和本机有界 Range 实测支持继续评估 Hugging Face 模型托管、SourceForge 完整安装器、GitHub 备用；这些证据不等于真实全球测速或服务保证。

jojo 同意本地实现与验证，并在看到构件、验证结果和未签名等限制后，于 2026-10-23 明确授权“推送合并发布，继续推进”。本轮先将已验证的 GitHub 构件作为未签名预发布测试包发布，不设为稳定版 Latest；HF/SourceForge 接入与付费渠道仍未确定。ADR-0015 的 GitHub 分发记录保留。

## 决定

- macOS 同一版本产出完整离线 DMG 与仅程序的更新 ZIP。DMG 内 `.app/Contents/Resources/offline-model` 携带固定版本 GGUF 和四件许可/校验文件，保持通常的拖入 Applications 操作。
- App 首次启动先校验、复制到 `userData/models`，最后原子提交模型；失败仍打开规则工具，设置状态保留具体错误和手动导入入口。推理仍在本机，模型仍只声明支持公式复核。
- 同一轮两种构件版本相同，不允许同版自动切换。未来更高版本通过不含模型的 ZIP 替换 `.app`，继续使用 `userData` 模型；不依赖差分更新成功来节省模型流量。
- 不在运行时删除签名 bundle 内的权重。模型更新不绑在 App 版本上；本切片不实现新的远端下载源或模型版本迁移。
- 本地工具仅准备构件，默认 CI 仍没有接入公开模型来源；保持手动更新、无自动下载。

## 考虑过的方案

| 方案 | 本地判断 | 原因 |
|---|---|---|
| 每次程序 ZIP 都带模型 | 不采用 | 每次全量回退仍可能重复下载 1.56 GB |
| DMG 根目录放模型，App 不带 | 不采用 | 只拖入 Applications 后弹出 DMG 会丢失首装载荷，需要额外操作 |
| 首装 `.app` 带模型，后续更新 ZIP 不带 | 实现原型 | 离线首用与标准安装操作兼容，后续流量不依赖差分 |
| 新增收费 CDN | 暂缓 | 目前先验证现有免费网络和客户端构件，付费不直接解决首装流程 |

此表由 agent 根据用户约束整理；jojo 已授权本切片推送、合并和预发布，尚未确认的新渠道不包含在本决定中。

## 代价与风险

首装 `.app` 与 userData 会各有一份权重，合计约 3.12 GB，另加程序、DMG 和安装临时空间。第一次更高版本 lean 更新替换旧 App 后，bundle 内副本才消失。启动复制有本地 I/O 等待；实际耗时需测量。新用户若只取得更新 ZIP，需要手动导入或以后单独提供的模型渠道。

旧版模型、更改模型文件名/哈希、回滚兼容策略另做切片；不自动用新模型替换未知模型。签名、公证、Gatekeeper、真实更新安装和全球下载均为独立发布关口。

## 重新评估的条件

若实际完整安装器超渠道单文件上限、首装空间/耗时不可接受、免费渠道不批准项目或实际下载不稳定，比较 `.pkg` 安装器、独立可恢复下载或按月限额的付费分发。绑卡、付费、上传和发布各按已有授权范围处理。

## 复盘（Q1–Q5）

### Q1. 上一版保留什么

保留固定版本、完整 SHA256、五文件许可包与不收集文件内容；GitHub 草稿暂保留为备用。

### Q2. 上一版缺什么

免费单文件托管只解决账单，不保证 App 下载完成率，也没有解除首装对网络的依赖。

### Q3. 技术差别是什么

首装载荷与程序更新 ZIP 物理分离，已校验模型存用户目录；不再每次程序更新重新携带模型。

### Q4. 何时回退

实际复制、离线重启、后续更高版本 App 复用或构件内容验收失败时，不发布该原型，保留现有本地导入。

### Q5. 遵守哪些教训

源代码、单测与静态配置不替代构件验收；本地构件通过不替代签名、公证、全球网络或生产更新验收。
