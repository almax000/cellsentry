# ADR-0020：桌面首发聚焦公式复核，移出工作簿 PII

## 背景

独立 PII/抽取任务已按 ADR-0019 拆出，但单文件扫描仍自动运行工作簿 PII，结果页仍有敏感项保护页签。jojo 在本轮批准包含完整桌面原型、规则质量、复核导出、官网和候选验收的两周方案；该提案明确建议把上述保护入口和默认扫描也移出首发。此前未回答的产品边界至此获得批准。

## 决定

首发工作流为选择 XLSX/CSV、规则扫描、工作表/单元格证据、可选本地 AI 意见、人工复核、报告或独立标记副本。默认扫描不运行 PII，结果页和导出不提供敏感项保护任务；PII 产品由 Vibli 承接。底层遗留代码可先保留，避免把产品收敛扩大成整仓删除。

Windows Microsoft Store 仍是首发目标。公司注册继续等待已有 DUNS 的邮件/同步，不走公司文件替代注册；Windows 实测环境由 jojo 后续提供。GitHub Actions 继续关闭，仅运行当前改动需要的本地静默检查。账号验证与正式 Store 获取/签名/更新验收仍是独立外部门槛。

先交完整桌面交互原型供 jojo 审阅，再实现主要界面。规则质量可独立推进，旧已揭盲诊断只作版本回归，不能充当新的保留集或用旧标签计算新版本准确率。内购、移动端和新模型训练继续后置。

## 接受的代价

CellSentry 首发用户暂不获得工作簿脱敏入口；审计用户需要另用 Vibli 处理隐私。旧版本仍须在支持页如实区分。切换会涉及单/批量扫描、取消、状态和导出回归，不能只隐藏页签。

## 后果与验收

- 新任务不发起 PII 引擎调用，UI 不出现 PII 进度/页签/导出；已有审计结果不受模型缺失、失败或取消影响。
- 人工结论、原公式证据与 AI 意见分别显示和导出；人工忽略不删除原始 finding，原文件不修改。
- 原型、生产实现和实际安装包分别记录，不以本 ADR 或原型存在声明已完成。

## 重新评估的条件

真实用户反复提供必须同一事务联动审计与脱敏的任务证据时，再提出新的产品决定；不因共享代码自动恢复入口。

## 复盘（Q1–Q5）

### Q1. 上一版做对了什么（这次保留）

独立产品、模型资源聚焦、本地处理和原文件保护继续保留。

### Q2. 上一版做错了什么

保留默认工作簿 PII 令“纯审计”在用户流程上仍有两条任务，也使代码状态与产品表述不同。

### Q3. 为什么这次不是同一个坑

验收同时覆盖实际引擎调用、扫描状态、导航和输出；不是只隐藏独立任务卡。

### Q4. 什么情况下回退

仅在前述真实联动需求得到产品确认后重新评估；不会因实现成本回退为双任务默认流程。

### Q5. 遵守了哪些教训

先确认范围与可审阅原型，质量与发行验证分开；已有编码不等于商店账号或应用审核通过。
