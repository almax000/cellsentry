## 背景

- 2026-10-18，第二轮调研评估了 TypeSafe 的 Jev 决策模型：它只能通过云端 API 调用，原文要发给第三方；据其公开的客户协议，也不允许用它的输出训练模型。
- 同一天 jojo 和 Black Sky 讨论后定了方向：做 Mac 和 iOS 两端的纯本地 AI PII 应用，先免费发布。jojo 的原话：“记住，我们的核心叙事是本地端侧推理，这是底线。所以你其他没验证的这几项，也要看看是否符合这个底线。”
- 随后主会话按这条底线，把所有没验证的事项逐条复核了一遍，见可行性测试文档 §5。

这条决定在 PRD 的 D1–D8 之前就定了，所以 PRD 里没有编号，ADR-0001 迁移时也没有覆盖到，这里补上。

## 决定

- 推理全程在用户自己的设备上完成。用户的文件和文件内容，任何时候都不发到任何服务器。
- 不做云端分析，连可选项也不做；不收集任何用户数据；不接 Apple Private Cloud Compute（PRD §4）。
- 唯一允许的联网：从 CellSentry 自有 CDN 下载模型（[ADR-0007](0007-own-task-models-on-own-cdn.md)）。模型固定版本、校验 SHA256，下载完成后全程离线。
- 自动更新默认关闭，只在用户手动点击时检查；网络访问白名单只留必要项（PRD §6）。
- 对外承诺写成：“你的文件从不离开设备。只有下载模型时才联网，而且只连 CellSentry 自己的服务器。”
- 这条承诺要能验证：发布前用断网和抓包各验收一次。
- 以后的任何方案和未验证事项，都先按这条底线复核。

## 考虑过的方案

| 方案 | 结果 | 理由 |
|---|---|---|
| 用 Jev 这类云端决策模型 | 否决 | 原文要上云，违背底线；专有服务，据其公开的客户协议不允许蒸馏 |
| 本地为主，提供“可选云端分析” | 否决 | PRD §4 写明连可选项也不做：只要有云端入口，“文件不出设备”就没法简单地验证 |
| Apple Private Cloud Compute | 否决 | 不算本地。Apple 的端侧系统模型算本地，但在中国大陆买的设备上用不了，只能做可选增强 |
| **纯本地端侧推理** | **采用** | 这是产品的核心叙事，也是和云端 AI 拉开差距的地方 |

当天 jojo 是用自己的话直接定的，没有给选项；这张表是起草时按调研和可行性测试文档补列的。

## 接受的代价

- 模型只能选能在 Mac 和 iPhone 上跑的小模型，效果上限比云端大模型低。第二轮调研 V5：现成的小 PII 模型在医疗文本上只有 0.41–0.48。
- 没有任何遥测，只能看 CDN 侧的汇总下载计数，判断真实使用情况很难（PRD §7）。
- 现在的代码还有不符合的地方：`app/electron/main/updater.ts` 在启动 30 秒后自动请求 GitHub 检查更新。这排在 [ADR-0008](0008-next-phase-order.md) 第 3 步“补上违背底线的地方”里修。

## 后果

**好处**：

- “不上传”是一个能用抓包验证的承诺，不只是一句宣传。
- 和 [ADR-0010](0010-free-and-open-source.md) 的开源配合：任何人都能核对代码里没有偷偷联网。

**风险**：

- #2 或 #3 可能证明，本地模型在目标设备上达不到 [ADR-0006](0006-pii-pass-bar-by-document-type.md) 的线，或者在 iPhone 上跑不动。

## 重新评估的条件

- 只有 jojo 明确改变这条底线时才重新评估。
- 技术上达不到时，收窄功能或平台，例如 iPhone 先只做规则版，而不是引入云端推理。
- 发布前的抓包发现，处理文件期间有任何网络请求：这是阻断发布的 bug，不是重新讨论底线的理由。

## 复盘（Q1–Q5）

不是复盘 ADR：这是第一次把本地底线写成决策，没有推翻任何决策。
