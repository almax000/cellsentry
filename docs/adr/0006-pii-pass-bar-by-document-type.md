## 背景

- Black Sky 的 issue #2 要回答：在 Mac 本地，“规则 + Julia-1 决策模型”能不能完成 PII 判断。需要一条事先写死的通过线。
- 第二轮调研 §3.2 提醒过，计分口径能把结论翻过来，所以召回一律按严格匹配算（片段边界和类型都对才算）。
- 三个选项都包含这几条，不在争议里：
  - 结构化标识（身份证、电话、社保、银行卡）在处理后的文档里一条都不能剩；
  - “规则 + Julia-1”不能比“规则 + 小型 token 分类模型”差；
  - 模型不超过 500 MB；
  - Mac 上每处理一千个候选不超过 2 秒。

## 决定

只有姓名、住址的召回和误报率是选出来的：

| 判据 | 达标线 |
|---|---|
| 姓名、住址的严格召回：表单和表格类（如体检报告首页） | ≥ 0.95 |
| 姓名、住址的严格召回：自由文本（如病历正文） | ≥ 0.85 |
| 阴性样本误报率（医生名、医院名、药名等） | ≤ 5% |

理由：
- 医疗档案大多是表单，这一类最应该稳。
- 病历正文最难，先给宽一点的线。
- 用户反正要逐条复核，漏报的代价比误报大。

2026-10-18 已同步到 issue #2 的正文和评论。

## 考虑过的方案

| 方案 | 结果 | 理由 |
|---|---|---|
| **按文档类型分开定** | **采用**（当时的推荐项） | 见上 |
| 统一 0.90，误报 ≤ 5% | 否决 | 原来写在 #2 里的版本，最简单；但对表单偏松，对病历正文可能过严 |
| 更严：统一 0.95，误报 ≤ 3% | 否决 | 医疗场景最稳妥；但决策模型路线很可能达不到，那样就要改走微调小型识别模型的备选路线 |

三行都是 2026-10-18 D5 问答的选项。

## 接受的代价

- 病历正文放宽到 0.85：每 100 个姓名、住址最多可能漏 15 个，要靠“我的信息”表和用户复核兜底。
- 评测集要按文档类型分层，两类分别出数。

## 后果

**好处**：

- 通过线和产品场景对得上：体检报告首页这类表单最常见，要求也最高。

**风险**：

- 如果评测集里表单和自由文本的比例和真实档案差很多，过线也说明不了真实效果。

## 重新评估的条件

- #2 的结果是“规则 + Julia-1”和“规则 + 小型 token 分类模型”都达不到线：要讨论是改线，还是改路线（例如微调 token 分类模型）。
- #1 的评测集显示，真实档案里自由文本的比例远高于“大多是表单”的假设。

## 复盘（Q1–Q5）

不是复盘 ADR：#2 原来的 0.90 是起草时的草案，还没被 jojo 定下。
