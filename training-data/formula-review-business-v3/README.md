# 中文业务背景与公式告警复核训练集 v3

针对外部数据评测暴露的误报问题，新生成 20 类业务场景，重点区分规则告警与有上下文支持的业务例外。这是一套带程序标签的合成数据，不是实际工作簿采样，也没有教师模型生成的标签。后续训练状态与结果以 `benchmark-results/formula-jev-business-v3/` 为准。

## 数量与使用方式

|文件|数量|用途|
|---|---:|---|
|train.jsonl|5520|4800 条新样本 + 720 条旧训练池回放|
|validation.jsonl|480|选择 checkpoint|
|test.jsonl|960|合成评测，不参与训练或选择|
|challenge.jsonl|240|带额外无关显示信息的呈现挑战，不参与训练或选择|
|benchmark.jsonl|180|保留原公式回归用例，模型输入和标签不变|

以上数量合计 7380 条。每个 split 另有同数量的 `*_chat.jsonl`，只是同一批样本的另一种表示，不是额外独立数据。训练时选择一种格式，不能把两种格式的数量相加。

全部分组真假各半。每类新场景在训练中有 120 对、验证 12 对、测试 24 对、挑战 6 对。新增数据的语言比例为中文 80%、英文 15%、中英混合 5%；720 条回放为原英文训练样本，所以最终训练池为中文 3840、英文 1440、混合 240 条。

## 覆盖场景及标签依据

|类别|判断依据|
|---|---|
|imported_literal|系统导入的固定数字是否与独立回执一致|
|contract_literal|固定录入的费用是否满足合同单价与月数|
|archived_snapshot|报表要求冻结签署快照，还是展示最新数值|
|iterative_cycle|是否启用迭代，线性自引用是否能收敛|
|external_link|离线缓存是否满足冻结交付，业务是否要求实时刷新|
|lookup_match|精确编号匹配与分档近似查找的口径|
|lookup_column|查找列越界、零列号及范围内取错字段|
|lookup_key_type|数字与文本编码、前导零的精确匹配|
|sum_scope|本期汇总范围与下期结转，遗漏或多算|
|aggregation_type|单据计数与金额求和|
|rate_scale|百分数存储方式与实际乘数|
|stored_sign|支出为正数或负数时的净额公式|
|date_order|起止日期映射与自然日差|
|optional_blank|跨境条件、金额门槛与字段必填规则|
|duplicate_key|订单级与商品明细级唯一键，真正的重复明细|
|seasonal_spike|旺季告警仍须与完整交易回执核对|
|rounding_tolerance|整数分值差异与合同允许的舍入容差|
|text_identifier|保留前导零的文本标识与必须参与计算的数值字段|
|empty_denominator|零分母场景要求返回零、空白或保留错误|
|unit_conversion|元与千元的换算契约|

每组两条样本只改变相关公式、观测值或业务契约，并分别形成正常与错误案例。没有把“迭代计算”“归档”“可选字段”一概视为免检：已启用但不收敛的循环、金额超过门槛的跨境空字段、错误的归档金额等仍是错误。实时与冻结报表均有正反例。

## 格式

Jev-style 候选格式与现有训练脚本兼容：`state`、`question`、`options` 是模型输入；`label` 指向正确候选。`is_error`、`oracle`、`facts`、`group`、`provenance`、`source_issue` 等是训练监督或审计元数据，不得整体塞入提示词。保留现有模型的英文候选措辞以便复用适配器；部分业务场景不止涉及狭义公式计算。

`*_chat.jsonl` 使用 `messages`，包含原始告警、单元格、表达式和背景；assistant 只输出布尔判断 JSON。该格式适合后续生成式 SFT，不表示当前 Jev 候选模型会生成文本，也不提供经过审核的解释文本。

## 隔离、校验与限制

- 生成器不会读取上传压缩包、其题目或答案。它只读取我们原来的 v1 **训练池**做回放，以及原 180 条公式用例作为回归基准。
- 新训练、验证、测试及挑战的配对分组、输入哈希、类别与业务事实哈希分别隔离。训练采用归档记录/台账呈现，验证采用表格，测试采用备忘录，挑战添加显示设置干扰。
- 这些拆分仍共享场景生成逻辑。模板、数值和行号变化不等于完全独立的语义分布；挑战集也不是新业务规则盲测。
- 外部数据包已经用于发现薄弱类别，因此今后应称为外部开发/回归评测，不能再宣称从未接触的新盲测。它没有被混入本训练集；后续应另准备独立人工标注的真实工作簿盲测。
- 7 项专项测试验证计数、成对隔离、独立公式/事实复算、仅回放旧训练、答案隔离、业务例外反例和文件哈希/聊天导出。
- 使用本机 CPM-jev tokenizer 检查全部 7380 条的两个候选，最长 320 token，均未超过 512，无截断。详见 `token-validation.json`。
- 所有标签对应已明示且足够确定的业务契约，没有生成“信息不足却强行二选一”的标签。实际部署若缺少这些背景，需要补充信息或拒判机制。
- 程序校验不代替独立人工审核，也不保证训练后一定提升。

## 复现与后续训练入口

```powershell
python scripts/generate_business_review.py
python -m unittest discover -s scripts -p 'test_business_review_data.py'
```

目录已有版本时生成器拒绝覆盖；确认要按相同规则重建本版本可用 `--replace`。重建后需要重新做 token 检查。`manifest.json` 保存各格式文件 SHA256 与旧数据来源哈希。

数据已兼容当前训练脚本的 `--data training-data/formula-review-business-v3` 参数，包含其要求的 benchmark，并有 challenge。初始适配器、学习率、回放比例和阈值仍应由验证集决定。生成步骤只产生和校验数据，不自动训练。随后按用户的 push 指令，将合成数据、脚本与评测报告保存至私有 GitHub；未包含模型权重、外部压缩包原文件或原始工作簿。

2026-10-15 后续训练由用户另行授权，从 `formula-jev-focus-v2b/best`（小迭代最佳 step 100）继续，已完成 690 步、每步 8 条、学习率 0.00002，完整使用 5520 条训练样本一遍。每 100 步验证，只按 validation 准确率和 NLL 选择 checkpoint，最终最佳为 step 400（累计见过 3200 条本轮训练样本）。旧合成测试、小迭代挑战、公开派生测试和上传数据包作为额外只读评测，全部不参与参数更新或模型选择。运行参数及初始化哈希见结果目录 `run-request.json`。

新合成测试 74.4% → 80.6%；外部全部审计 65.7% → 69.4%，但外部公式子集仅 85.2% → 85.3%，公式误报 75 → 78。因此没有证明目标公式误报复核提升。详见 [本轮结果与限制](../../benchmark-results/formula-jev-business-v3/overview.md)。
