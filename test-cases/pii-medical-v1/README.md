# 中文医疗 PII 合成基准 v1 数据卡

用于 Issue #1 的文本层评测，以及 #2 后续规则/Julia-1/token 分类模型对比。2026-10-19 本地脚本生成，种子 `20261019`，不读取真实资料、不调用模型或网络。测试哈希已在运行基线前登记到 [Issue #1](https://github.com/almax000/cellsentry-dev/issues/1#issuecomment-6264034185)。

| 分组 | 文档 | 表单/表格/自由文本 | 正例跨度 | 易混阴性跨度 | 纯阴性文档 | 医疗文档 |
|---|---:|---|---:|---:|---:|---:|
| dev | 120 | 40 / 40 / 40 | 1,120 | 1,080 | 24 | 102 |
| test | 360 | 120 / 120 / 120 | 3,360 | 3,240 | 72 | 300 |

正例七类：姓名、手机/座机、身份证、国内社保卡号、银行卡、邮箱、住址；测试各 480 个。测试身份证中 360 个校验位正确、120 个错误，患者栏中两者均需保护。银行卡均通过 Luhn。阴性九类：医生名、医院名、历史公众人物、药名、检验值、手机号外形订单号、其他 11 位数字、公共地点、错误校验位教学代码。

范围为患者及家属隐私；医生、机构与医疗术语按本 issue 要求作为背景阴性，不是通用“所有人的姓名都属于 PII”语料。患者标识按**实际出现的值**标注，不包含字段名、引号或分隔符。校验教学代码无个人关联，按阴性处理；不能只用身份证校验通过与否代替隐私判定。

`dev.jsonl` / `test.jsonl` 含 gold，`*.inputs.jsonl` 只含 id、layout、document_type、text、units，可提供给模型。units 保留字段/单元格/句子边界、表头和表格坐标；有患者行的表格包含 3 行，纯阴性表格只有背景记录。**跨度统一使用 UTF-16 code units、左闭右开，不做 Unicode/空白归一化。**

dev/test 正例值没有完全相同的交叉值，文档组独立，字段用语和文档模板分开；仍由同一生成器产生，不能据此宣称模板/语义独立。原有两项目的 PII 160 题完全相同，且按单元格而非跨度计分、已参与研发回归，故未并入新冻结集；记录见 `legacy-sources.json`。

已知局限：有限模板、均匀类型分布，非自然患病/文档分布；地址为明确虚构地名，社保卡号仅一种简化格式；dev/test 使用不同出生年份区间及姓名尾字池以隔离正例值。生成号码无真实记录来源，但不代表已核实为空号或未发放号码。每份文档均包含九种背景，其中含符合手机格式的订单号，是刻意的上下文压力测试，不能把阴性误报率解释为自然资料发生率。合成标签未经独立医学/隐私专家审核。

表格以带表头的规范文本冻结，可用 CLI 导出真实 xlsx 到本地 `.runtime/`；导出二进制不作为额外独立样本，gold 仍对齐规范文本。**本版无 OCR，不测 PDF/图片实际脱敏，也不测 Mac/iPhone 性能。**

生成/验证/评分/xlsx 导出和预测格式见 [评测协议](../../docs/evaluation/2026-10-19-pii-benchmark-protocol.md)；现有规则组件基线见 [报告](../../benchmark-results/pii-medical-v1/report.md)。冻结目录禁止覆盖，新语料使用新版本目录。
